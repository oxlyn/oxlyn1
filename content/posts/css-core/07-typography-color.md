> 本文对应 MDN 指南[颜色](https://developer.mozilla.org/zh-CN/docs/Web/CSS/Guides/Colors)与文字相关属性文档。

**学习目标**：搭一套不依赖具体字体的字体栈，掌握行高与排版的纪律，用 oklch 组织颜色体系。

## 字体栈：从"指定字体"到"指定气质"

`font-family` 的本质是**逐个回退**：浏览器从左到右找第一个可用的字体，所以栈的末尾永远挂通用族（`sans-serif/serif/monospace`）兜底：

```css
body {
  font-family: system-ui, -apple-system, "Segoe UI", Roboto,
               "PingFang SC", "Microsoft YaHei", sans-serif;
}
code, pre { font-family: ui-monospace, "SF Mono", Consolas, monospace; }
```

要点：**系统字体栈**（system-ui 打头）零加载成本且观感原生；中文字体排在西文之后（西文字体不含汉字，汉字落到后面的中文字体——这个顺序正好实现"西文用 A 字体、中文用 B 字体"的混排）；`font-display: swap` 让 Web 字体加载期间先显示兜底字，避免白屏。

排版三纪律：

- **行长 45–75 字符**（`max-width: 65ch` 是甜点位）——超长行是可读性头号杀手；
- **行高 1.5–1.8**（正文），标题可收到 1.2；无单位值让行高随字号自动缩放；
- **字号阶梯用 rem**（第 1 章），正文最小 1rem——别用 12px 折磨用户。

## 颜色：oklch 为什么是未来

传统 hex/rgb 的问题：**数值与感知无关**——`#0000ff`（蓝）看起来比 `#ffff00`（黄）暗得多，"把亮度调低 20%"这种操作在 RGB 里是玄学。oklch（感知均匀色彩空间）把颜色拆成三个正交维度：

```css
:root {
  --brand-500: oklch(62% 0.19 258);   /* L 亮度 / C 饱和度 / H 色相 */
  --brand-600: oklch(55% 0.19 258);   /* 只降亮度 → 天然的 darker 色阶 */
  --brand-hover: oklch(62% 0.19 268); /* 只移色相 → 和谐的邻近色 */
}
```

- **L（Lightness）**：感知亮度 0–100%，色阶体系（50–950）就是等差 L——Tailwind 的色阶、[Tailwind 第 6 章](/posts/tailwind-css/06-theme-customization.md)的品牌色五档，本质都是这条 L 轴；
- **C（Chroma）**：饱和度上限随亮度自动收敛，高亮/极暗区域不会"炸色"；
- **H（Hue）**：色相 0–360，转 H 就是和谐换色。

**同亮度跨色相等宽**是暗色模式的最大红利：亮色主题下选好对比度，暗色主题在 oklch 里保持 L 值镜像（亮字 83%、暗底 24%），对比度自动合规——本站 global.css 的暗色变量表（`oklch(83.5% 0 264)` 文字 / `oklch(23.6% 0.005 248)` 背景）就是活例。

## 对比度：可读性的硬指标

文字与背景的对比度按 WCAG 验收：**正文至少 4.5:1，大字 3:1**。oklch 的 L 差可以粗略估算对比度（L 差 ≥ 60% 基本安全），精确值用浏览器 DevTools 的对比度检查器（点颜色样本即出）。灰色文字陷阱：`#999` 在白底上 2.8:1——大面积正文请用 500 档以内的灰。

## 半透明与混合

`color-mix()` 是现代调色神器：`color-mix(in oklch, var(--brand) 80%, white)`——品牌色直接派生浅色阶，不用手工造色。`/` 透明度语法（`oklch(62% 0.19 258 / 0.5)`）与 `color-mix` 组合可以覆盖绝大多数"渐变过渡色"需求。

## 踩坑提示

- 中文字号×西文字体栈：把中文字体放前面会导致西文也用中文字体的拉丁字形——顺序即混排策略。
- 行高写成 px：字号一变行高不跟，多行文字挤成饼——无单位行高是纪律。
- 暗色模式下"反色"用纯白：oklch 下亮色应止步 L 93–96%，纯白刺眼。

## 练习

1. 用 oklch 手工造一个品牌色的 50/500/950 三档（固定 C/H、只动 L），对比 Tailwind 色阶。
2. 给正文设置 `max-width: 65ch` + 行高 1.75，与改造前的阅读舒适度对比。
3. 用 DevTools 对比度检查器找出自己页面里不达标的灰色文字并修复。
