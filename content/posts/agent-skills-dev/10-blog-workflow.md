> 本文无单一官方对应，是全系列综合实战；规范出处见各章官方链接。

**学习目标**：把前九章的方法论用在真实工作流上——为一个真实站点编写一套技能库，走完"规范→技能→回归→发布"全流程。

## 需求：把站点规范变成技能

本站每篇教程都遵守一套明文约定：总览+10 章+附录的固定结构、"系列名 · 第 N 章：标题"的命名法、一天一篇连续连载的 publishDate、章末"踩坑提示+练习"、官方文档链接置顶……过去这些规范活在作者脑子里和几篇 README 里，每写一个新系列都要人工对齐。**这正是技能的标准猎物**：多步骤、有明确规范、反复执行、产出可校验。

## series-planner：主技能

```text
series-planner/
├── SKILL.md
├── references/
│   ├── structure.md        # 总览+10 章+附录的结构细则
│   ├── naming.md           # 标题/文件名/时间线规则
│   └── style.md            # 文风：引用块、学习目标、踩坑+练习
└── assets/
    └── outline.template.md # 大纲模板（章节导航表骨架）
```

SKILL.md（导航式，第 5 章）的骨架：

````markdown
---
name: series-planner
description: 为技术博客规划新教程系列，产出"总览+10 章+附录"的完整大纲（章节导航表、时间线、官方文档对应）。当用户说"写个新系列""规划教程"或要求生成系列大纲时使用；单篇文章写作不适用。
metadata:
  version: 1.2.0
---

# 系列大纲规划

当前已有序列（自动注入，时间线顺延其后）：

```!`ls content/posts/`
```

## 流程

1. 与用户确认主题、定位与前置系列，读 references/naming.md 定系列名与 slug；
2. 按三主线切 10 章，每章一句话定位 + 官方文档对应链接；
3. 套 assets/outline.template.md 产出总览（章节导航表三列：章节/内容/官方对应）；
4. 结构与文风细则见 references/structure.md 与 references/style.md；
5. 产出后自查：publishDate 连续且顺延、文件名前缀连续、无与既有系列重叠的主题。

## 常见错误（自查后修正）

- 章节标题与既有系列撞主题——先检索再动笔
- 总览里写"第 0 章"——结构只有总览+1~10+附录
- 官方链接指向失效路径——只引官方域名下的稳定页面
````

注意第 10 行的**动态上下文注入**（第 6 章）：技能自带"站点现状"，不用人工粘贴目录列表。12 章文件名与 `publishDate` 时间线的计算规则全部写在 references/naming.md，配合 `scripts/validate_frontmatter.mjs`（第 2、6 章的校验脚本）做产出后校验——**判断力归 AI，格式归脚本**。

## chapter-writer：配套技能

写完大纲后的第二跳：`chapter-writer` 按大纲写单章正文。它的 description 与 series-planner 互划边界（"单篇章节写作，不含系列规划"，第 3 章的排他反例），正文是第 4 章的任务书结构：开头官方链接引用块 → 学习目标 → 章节主体要求 → 踩坑提示 → 练习，外加一条防呆："跨系列引用一律用 `/posts/<slug>/` 目录形式，先确认目标章节存在"。

## 全流程跑一遍

```text
1. "帮我规划一个 X 主题的新系列"      → series-planner 激活（自动触发 ✓）
2. 注入目录清单 → 三主线切章 → 产出大纲
3. 校验脚本跑大纲内所有 frontmatter    → OK / FAIL 逐条修复（脚本契约 ✓）
4. "按大纲写第 1 章"                  → chapter-writer 激活
5. 对照 TESTING.md 回归四象限          → 全绿后交付（回归 ✓）
```

这套技能库上线后的真实收益：新系列大纲从"人工一晚"变成"对话十分钟 + 人工精修"，且**格式零漂移**——规范从人的记忆迁移进了版本管理的文件。

## 收官回顾

九章走过的路，在这一章全部合流：技能解剖与分工（1）→ 第一个技能（2）→ 描述路由（3）→ 指令写作（4）→ 渐进披露（5）→ 脚本化（6）→ 组合复用（7）→ 调试回归（8）→ 发布兼容（9）→ 本章的实战整合。往后的路：把更多工作流技能化（部署检查、周报、代码评审），并回到[《从零实现 Agent》](/posts/agent-from-scratch/)的视角思考——**你的技能库就是你自己这个 Agent 的上下文工程**（[MCP 系列](/posts/mcp-dev/07-context/)第 7 章的命题，在个人生产力层的重演）。

## 踩坑提示

- 一次写十个技能再统一调试——先让一个技能全绿，再横向复制方法；
- 把"写文章"的创意判断也编码成规则——技能管规范与格式，选题与见解仍是人的事；
- 技能库上线后不再迭代——第一次真实使用就会产生新的防呆条文，安排每周一次的"技能回溯"。

## 练习

1. 按本章结构完成 series-planner 与 chapter-writer，跑通"规划→产出→校验→写作"全流程。
2. 用你的真实工作流（不一定是博客）重复一次需求分析，产出第三个技能并走完回归。
3. 给技能库做一次月度审计：过时的防呆条款删除、新增的踩坑入册、metadata 版本号统一升位。
