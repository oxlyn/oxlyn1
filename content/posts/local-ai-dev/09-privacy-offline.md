> 本章是架构综合：PWA 组合参考 [web.dev 的 PWA 指南](https://web.dev/learn/pwa)；数据分级呼应[《MCP 开发入门》第 8 章](/posts/mcp-dev/08-security/)。

**学习目标**：建立"数据分级"的架构方法，把本地推理与 PWA 组合成真正的离线应用，设计本地/云端混合的分工策略。

本地推理的能力天花板决定了它不可能包揽一切。**隐私架构的艺术不是"全本地"，而是分级**：什么数据永远不出设备、什么可以上云、什么由用户决定——本章把前三章的技术件组织成这个决策体系。

## 数据分级：架构的第一张表

| 级别 | 数据举例 | 推理策略 | notes 里的对应 |
| --- | --- | --- | --- |
| **不出设备** | 笔记原文、私人对话、录音 | [WebLLM](/posts/local-ai-dev/05-webllm/) / [内置 AI](/posts/local-ai-dev/07-chrome-prompt-api/) / 本地 Ollama | 笔记全文的摘要、分类、语义检索 |
| **脱敏后可出** | 匿名化的统计、错误堆栈 | 云端模型 | 用户行为分析（去标识后） |
| **用户显式授权才出** | 明确标记"云端增强"的内容 | 云端旗舰模型 | "用最强模型润色这条笔记"按钮 |
| **永不进上下文** | 密码、密钥、支付信息 | —— | 不参与任何 AI 功能 |

设计流程：把每个 AI 功能对照这张表过一遍，**默认最低级别，升级需显式交互**——[MCP 第 8 章](/posts/mcp-dev/08-security/)的"最小权限"在这里变成"最小数据流"。关键是第三级的设计：**升级动作要可见、可撤销**，用户对"这条内容去了云端"有知情权。

## 混合架构：本地打底，云端增强

```text
┌─ 本地层（默认）─────────────────────┐
│ WebLLM / Prompt API / Ollama        │
│ 摘要、分类、语义检索、简单问答        │
├─ 云端层（显式触发）─────────────────┤
│ 旗舰模型 API                        │
│ 复杂推理、长文创作、多模态            │
└────────────────────────────────────┘
        路由器：任务分类 + 数据级别 + 设备能力
```

路由器的三个输入：**数据级别**（上表）、**任务难度**（本地模型的[能力边界](/posts/local-ai-dev/01-why-local/)）、**设备能力**（[第 4 章分级检测](/posts/local-ai-dev/04-webgpu/)）。输出是执行位置。[评测第 10 章](/posts/evals-dev/10-red-team/)的安全回归同样分层跑——本地模型与云端模型的安全基线分开建。

## PWA：离线推理的最后一块拼图

本地推理的承诺是"断网也能用"——前提是**应用本身也离线可用**：

- **Service Worker 缓存**：应用外壳与静态资源 precache，权重在 Cache Storage（[第 5 章](/posts/local-ai-dev/05-webllm/)的模型缓存同理）；
- **IndexedDB 存数据**：笔记与向量本地持久化（[localStorage 的升级](/posts/local-ai-dev/06-browser-agent/)）；
- **后台同步**：联网时把"待同步队列"（用户显式授权上云的部分）补传。

三者齐了，notes 才是真正的**离线优先 AI 应用**：断网状态下，记笔记、搜索、摘要、对话全部照常。

## 一个诚实的成本表

| | 纯本地 | 纯云端 | 混合 |
| --- | --- | --- | --- |
| 隐私 | 满分 | 依赖供应商 | 分级可评 |
| 质量 | 天花板低 | 旗舰水准 | 逐任务最优 |
| 离线 | 完整支持 | 无 | 大部分功能 |
| 运维 | 模型管理在自己 | 供应商托管 | 双份 |
| 首次体验 | 下载成本高 | 即开即用 | 按需 |

**没有全赢**——混合架构的复杂性（两套推理、路由器、同步）是真实的，团队规模与数据敏感度决定它值不值。个人工具从纯本地起步足够；面向行业（医疗/法律）的混合是合规刚需。

## 踩坑提示

- 分级表只有"本地/云端"两档——用户授权级是隐私架构的核心，别替用户决定一切；
- PWA 缓存了应用没缓存权重——断网后模型加载失败，权重缓存策略与应用同步设计；
- 混合路由器不透明——用户不知道当前在用哪个模型，状态栏显式标注（也是信任建设）；
- 本地推理的失败静默降级到云端——把"用户标记为不出设备"的数据也送了上去，**分级表必须有运行时强制**，不是文档约定。

## 练习

1. 给 notes 全部 AI 功能填一遍数据分级表，找出至少一个"应该降级"的设计。
2. 实现路由器最小版：设备检测 + 任务类型 → 本地/云端/拒绝三路输出。
3. 断网测试：关掉网络跑一遍 notes 全功能，记录每个功能的离线状态与失败方式。
