> 本章对应 OpenAI[评测指南](https://platform.openai.com/docs/guides/evals)的 model comparison 部分与业界成对评测共识（换序去偏见 [OpenLayer 指南](https://www.openlayer.com/blog/llm-as-judge-evaluation-guide)）。

**学习目标**：掌握"版本 A 是否真的更好"的判定方法——换序成对比较、胜率统计与样本量常识，建立留出集防过拟合的纪律。

"感觉 v2 更好"在第 1 章被驳倒了；本章给出它的替代品：**同一用例集、同一裁判、两个版本，让数字说话**。

## 成对比较与换序

A/B 的被测对象可以是提示词两版、两个模型、两种检索策略——对评测设施而言只是两个 `subject` 函数。判定用[第 4 章](/posts/evals-dev/04-llm-as-judge/)的裁判做**成对比较**，并严格执行换序：

```ts
export async function pairwise(judgeFn, a, b, input) {
  const ab = await judgeFn(input, a, b)   // "A 在前"的比较
  const ba = await judgeFn(input, b, a)   // 换序再评一次
  if (ab === ba) return ab                // 一致才计入：win/lose/tie
  return "inconsistent"                   // 换序后翻供 → 位置偏差介入，记平
}
```

换序一致性本身就是裁判质量的体检：**不一致率居高不下说明裁判不可信**，先回去修裁判（锚点、依据引用），别急着看胜率。

## 胜率与样本量常识

跑完 N 条用例，得到 v2 的胜率。三条不玄学的统计常识：

- **个位数样本没有结论**——5 条全胜也可能只是运气；30 条起看趋势，100 条才谈稳定；
- **关心的是差距不是绝值**——70% vs 50% 的胜率差，比"90% 但样本 10 条"可信；
- **平局不是浪费**——大量 tie 说明两版本差异不在这些用例覆盖的维度上，该补用例而不是硬下结论。

工程结论的表达永远是"**在 XX 用例集上，v2 对 v1 胜率 +18%（n=120，换序一致率 92%）**"——条件、样本、质量指标三位一体，缺一即是伪数字。

## 留出集：防"考试过拟合"

用例集被反复用于调优后，会被无意识地"刷"——改动只对已见过的用例有效。防法照搬机器学习的老规矩：

```text
用例池 100 条 → 随机切分：回归集 80（随便跑） + 留出集 20（锁起来）
调优只看回归集 → 候选版本定稿前跑一次留出集
回归集大涨、留出集不涨 = 过拟合，该版本不发布
```

留出集要**定期轮换**（把留出升回归、新用例进留出），避免它也慢慢被"看熟"。

## 参数化矩阵：一次看清维度

改动往往不止一个轴（提示词 × 模型 × 温度）。runner 的参数化能力让矩阵一次跑完：

| | GPT 系 | Claude 系 | 本地模型 |
| --- | --- | --- | --- |
| 提示词 v1 | 0.82 | 0.84 | 0.71 |
| 提示词 v2 | **0.89** | 0.87 | 0.74 |

读矩阵比读单点更有信息量：v2 的提升集中在哪个模型上、哪个组合是性价比拐点、贵模型的优势是否值得——**矩阵是模型选型与提示词调优的合并决策表**。注意每格都要跑全量回归集，矩阵的成本是指数的，冒烟集先粗筛再精跑。

## 踩坑提示

- A/B 只换了提示词却顺手换了温度——单变量原则，一次只动一个轴；
- 胜率报告不带样本量与一致率——无法复核的数字等于没说；
- 留出集泄露进日常回归——它就退化成第二个回归集，过拟合检测失效；
- 对一个用例反复改提示词直到通过——这是在背题，不是在改进（第 2 章"用例即考试"的反面）。

## 练习

1. 用第 5 章 runner 跑一次真 A/B：v1 提示词 vs 加了"引用原文"要求的 v2，输出带一致率的胜率报告。
2. 把用例集切成回归 + 留出两份，验证一次"回归集提升但留出集持平"的过拟合场景（故意只在回归用例上调优）。
3. 跑一个 2×2 参数化矩阵（两版提示词 × 两个模型），从矩阵读出一条单点测试看不出的结论。
