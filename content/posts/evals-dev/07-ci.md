> 本章是工程实践综合：CI 门禁思路与 [promptfoo 的 CI 用法](https://www.promptfoo.dev/docs/integration/ci-cd/)一致；示例为 GitHub Actions 风格。

**学习目标**：把评测从"本地手动跑"升级为"仓库门禁"——PR 跑冒烟、夜间跑全量、分数低于基线自动拦下，让"改提示词 = 改代码"落地成流程。

第 5 章的 runner 一条命令就能跑，接 CI 只差三件事：**什么时候跑（触发）、跑多少（分层）、拦不拦（门禁）**。

## 双轨：PR 冒烟 + 夜间全量

全量评测又慢又贵，每次提交都跑会把 CI 拖死。行业共识是双轨：

```yaml
# GitHub Actions 风格
jobs:
  eval-smoke:                        # 每个 PR：秒级~分钟级
    steps:
      - run: node runner.mjs cases/all.jsonl --tags smoke --gate baseline.json
  eval-nightly:                      # 夜间：回归 + 全量 + 留出集
    if: github.event_name == 'schedule'
    steps:
      - run: node runner.mjs cases/all.jsonl --tags regression --gate baseline.json
      - run: node runner.mjs cases/all.jsonl --tags full
```

- **PR 冒烟**：只跑 tags 含 smoke 的 5~10 条，分钟级反馈——拦住"明显搞坏"的改动；
- **夜间全量**：完整回归 + 留出集 + 昂贵的裁判密集用例，早上看报告——捕捉冒烟层的盲区；
- 裁判密集的评测永远留在夜间层（成本与时长都不适合 PR 节奏）。

## 门禁：基线文件与退出码

"分数低于基线即拦下"需要一个**显式的基线**：

```json
{
  "note-add": { "min": 0.9 },
  "note-search": { "min": 0.85 },
  "overall": { "min": 0.88 }
}
```

runner 的 `--gate` 参数逐组比对，任一组低于基线即退出码 1——CI 天然把它变成红叉。两条管理纪律：

- **基线改动 = 显式提交**：基线只能随"评测集扩充"或"有意的行为变更"上调，PR 里写清原因——它是质量的宪法条款；
- **分数小幅波动是常态**：概率产出天然抖动（温度、模型侧变化），门禁阈值要给带宽（如 0.90 基线 + ±0.02 容忍带），拦"显著退化"而不是"数值噪声"。

## 报告产物：让人看得见

CI 里最有价值的产物是**可点击的对比报告**（第 5 章的 markdown 报告）：

- PR 评论/Job 摘要里贴"本次 vs 基线"的分数表 + 失败样本链接；
- 失败用例的产出原文进 artifact，排查不进生产日志；
- 趋势可视化（哪怕只是把每日平均分追加进一个 csv）——缓慢的漂移只有趋势图能暴露。

## 改提示词 = 改代码

双轨 + 门禁落成后，团队纪律随之升级——**提示词文件与代码同权**：

- 改 prompt 走 PR，冒烟绿了才能合；
- PR 描述写清"动了什么、预期影响哪组分数"；
- 意外提升也要看：分数无故上涨说明被测方或评测本身出了状况（模型静默更新、用例被改坏），调查后再庆祝。

到这一步，[Agent Skills 第 8 章](/posts/agent-skills-dev/08-debugging/)的手工回归清单完成了自动化升级：清单的四个象限变成 tags，人工勾选变成退出码。**测试系列**（筹备中）的 Vitest/Playwright 将在同一 CI 里并列跑——代码测试与评测门禁各管半边。

## 踩坑提示

- 门禁阈值设满分——概率性产出下天天红灯，团队很快学会"无视 CI"，门禁失去权威性；
- 冒烟集太重——PR 等十分钟，人就开始找跳过 CI 的借口；
- 夜间全量没人看——跑而不看是负资产，报告必须送进有人看的渠道（评论、群、邮件摘要）；
- 评测密钥明文进 workflow 文件——用平台的 secret 机制，与[生产配置](/posts/nuxt-dev/06-state-and-config/)同一纪律。

## 练习

1. 给第 5 章的 runner 补 `--gate` 实现（分组比对 + 容忍带 + 退出码），本地验证拦下与放行两种路径。
2. 写一个最小 workflow：PR 触发冒烟门禁，把 markdown 报告作为 PR 评论发布。
3. 制造一次"静默退化"（把某条提示词改坏），体验夜间全量如何抓到冒烟层的漏网之鱼。
