> 本章是工程实践综合；trace 字段设计与 [Agent 系列第 6 章](/posts/agent-from-scratch/06-session-log/)的会话日志一脉相承。

**学习目标**：给线上应用装上"黑匣子"——结构化 trace，建立"生产数据 → 评测用例 → 质量提升"的数据飞轮，并用在线指标补离线评测的盲区。

离线评测（前七章）回答"我改的东西在已知用例上表现如何"；生产环境回答的是另一个问题——**"用户真正在问什么、哪里翻车"**。两者靠数据飞轮连接：线上发现盲区 → 回流成用例 → 评测防复发。

## trace：一次调用的完整黑匣子

[Agent 系列第 6 章](/posts/agent-from-scratch/06-session-log/)写过一个会话日志的雏形；评测视角下，trace 要补齐"复现与判分"所需的全部字段：

```jsonc
{
  "id": "tr_20261130_0001",
  "input": "我之前记过关于租车的笔记吗",
  "output": { "text": "找到了 2 条相关笔记……", "toolCalls": [
    { "name": "search_notes", "arguments": { "keyword": "租车" } } ] },
  "meta": { "model": "…", "promptVersion": "v7", "temperature": 0.2,
            "latencyMs": 1830, "tokensIn": 1420, "tokensOut": 96, "costUsd": 0.004 },
  "feedback": { "thumbs": "up", "adopted": true },
  "sampling": { "pool": "all", "kept": true }
}
```

三组字段对应三种消费：`input/output` 供回流评测、`meta` 供成本与延迟趋势、`feedback` 供在线指标。**promptVersion 必须记录**——没有版本号的历史数据无法归因，[第 6 章](/posts/evals-dev/06-ab-compare/)的对比全部失效。

## 在线指标：离线评测的盲区补丁

离线用例集永远滞后于用户的真实分布。三类在线指标实时补位：

- **反馈类**：点赞/点踩、纠错率——直接的用户质量信号；
- **行为类**：采纳率（AI 的建议被用了没）、重试率（同一问连问三次=失败信号）、中止率（答一半就关掉）；
- **成本与延迟**：token、耗时分布——退化常先在成本曲线显形（[MCP 第 7 章](/posts/mcp-dev/07-context/)的上下文经济在生产的倒影）。

这些指标**不是评测的替代**，而是"哪里需要新用例"的雷达：重试率突增的工具调用场景，就该有对应的离线用例了。

## 数据飞轮

```text
生产 trace ──(采样/用户差评/重试率异常)──▶ 候选用例
    │                                        │ 脱敏 + 人工审核 + 打标准
    │                                        ▼
在线指标（雷达）                        回归用例集 ◀── 事故回放
    │                                        │
    └────────── 版本迭代 ◀── CI 门禁 ◀── 离线评测 ──┘
```

落地的关键是**采样策略**（全量存太贵）：差评必留、重试必留、随机抽 1%~5% 常规流量。回流的每条 trace 要过**人工审核**才能进用例集——用户输入是原料，用例是食品，中间必须有人。审核顺带完成第 2 章的打标（层级、类型）与脱敏。

## 平台与自研

观测层的产品生态已经成熟（LangSmith、Braintrust、Arize 等提供 trace 存储、在线评测、数据集管理的托管组合），OpenTelemetry 的 GenAI 语义约定也在统一 trace 格式。自研派（本系列路线）用[第 5 章](/posts/evals-dev/05-runner/)的 runner 加一张 trace 表就能起飞——**选型的判断标准不是功能多少，而是"trace 能否无痛变成用例"**：飞轮转不转，取决于这条路径顺不顺。

## 踩坑提示

- trace 只存回答不存输入与参数——无法复现、无法回流，黑匣子变成黑盒；
- promptVersion 与代码不同步（改了提示词没升版本号）——历史数据全部失去归因价值；
- 回流用例不审核直接进集——脏数据污染基线，门禁被噪音击穿；
- 在线指标直接当门禁——用户反馈噪声大、样本偏，它指方向，判分仍靠离线。

## 练习

1. 给你的 notes 应用补全 trace 结构（含 promptVersion），跑一天真实使用，导出全部 trace。
2. 从 trace 里筛出 3 条重试/差评样本，审核脱敏后回流进用例集，跑一次回归确认当前版本的表现。
3. 设计你自己的采样策略（差评必留 + 随机 N%），计算一个月的 trace 存储量与回流人工成本。
